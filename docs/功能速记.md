# shared-auth 功能速记

本文汇总 shared-auth 当前已经实现的功能，用于快速复习项目流程和准备面试。系统目前只支持邮箱账号，由 JobPilot 和 StudyFlow 共同使用。

## 1. 邮箱注册

用户先申请邮箱验证码，系统生成六位验证码，将验证码的 HMAC 保存到数据库，并通过 Resend 或开发收件箱发送。验证码通过后，系统使用 bcrypt 保存密码摘要，在一个数据库事务中创建用户 UUID、邮箱身份和首个登录会话，随后返回短期 Access Token，并把长期 Refresh Token 写入 HttpOnly Cookie。

**一句话记忆：** 验证邮箱归属后创建共享用户 UUID，同时建立登录会话并签发两种令牌。

## 2. 邮箱登录

用户输入邮箱和密码。系统统一邮箱格式，根据邮箱查找账号，再使用 bcrypt 比较密码；验证成功后创建新的登录会话，返回短期 Access Token，并把长期 Refresh Token 写入当前应用专属的 HttpOnly Cookie。邮箱不存在、密码错误和账号不可用统一返回“邮箱或密码错误”。

**一句话记忆：** 查邮箱、验密码、建会话、发令牌，并用统一错误避免泄露账号是否存在。

## 3. 自动续期

Access Token 过期后，前端使用浏览器 Cookie 中的 Refresh Token 请求续期。系统检查会话、应用、有效期和令牌摘要，通过数据库原子更新将旧 Refresh Token 替换为新的，再签发新的 Access Token；同一个旧令牌重复使用或并发刷新时只允许一次成功。

**一句话记忆：** 用长期令牌换短期令牌，并且每次续期都轮换长期令牌。

## 4. 退出登录

用户退出时，系统使用当前应用的 Refresh Token 找到并撤销当前会话，然后清除对应 Cookie。退出操作可以重复调用，不会影响另一个应用或其他设备的会话；已经签发的 Access Token 最长仍可能使用到自身过期。

**一句话记忆：** 撤销当前应用、当前设备的刷新会话，并清除浏览器 Cookie。

## 5. 查看当前账号

前端携带 Access Token 调用 `/auth/v1/me`。系统验证 JWT 的 RS256 签名、签发者、有效期和应用来源，从令牌中取得用户 UUID，再查询数据库并返回账号状态和已验证邮箱。JobPilot 和 StudyFlow 使用同一个 UUID 关联各自的业务数据。

**一句话记忆：** 验证 Access Token 后，根据稳定 UUID 返回当前认证账号信息。

## 6. 忘记密码与重置密码

用户先申请密码重置验证码，再提交验证任务 ID、验证码和新密码。系统检查验证码的用途、有效期、使用状态和错误次数，使用 bcrypt 保存新密码，并撤销该用户在 JobPilot、StudyFlow 和所有设备上的全部刷新会话，要求重新登录。

**一句话记忆：** 用邮箱验证码证明身份，修改密码后让所有旧会话失效。

## 7. JWKS 公钥

shared-auth 使用 RSA 私钥签发 RS256 Access Token，并通过 `/.well-known/jwks.json` 公开对应公钥。JobPilot 和 StudyFlow 可以缓存公钥，在本地验证令牌签名、有效期和受众，再从 `sub` 中读取用户 UUID，不需要每个业务请求都回调认证服务。

**一句话记忆：** 认证服务用私钥签发令牌，业务服务用公开的公钥在本地验签。

## 8. 服务健康检查

`/health/live` 只判断 shared-auth 进程和 HTTP 服务是否仍能响应；`/health/ready` 还会检查 PostgreSQL 是否可用。Docker Compose 使用就绪检查判断认证服务能否接收请求，数据库暂时不可用时返回 503，但不会把它误判为程序已经崩溃。

**一句话记忆：** `live` 判断程序活没活，`ready` 判断数据库就绪后能不能干活。

## 9. 开发验证码收件箱

开发模式下，验证码不会发送到真实邮箱，而是暂存在进程内存中，开发人员和自动化测试可以通过 `/dev/outbox` 读取。使用 Resend 时该接口不会注册，生产环境也禁止开启，以免验证码被公开读取。

**一句话记忆：** 本地用内存假邮箱跑完整验证码流程，真实邮件模式和生产环境自动关闭。

## 10. 注销账号

用户携带 Access Token 并再次输入当前密码。验证通过后，系统永久删除 shared-auth 中的用户、邮箱身份以及 JobPilot、StudyFlow 和所有设备的刷新会话，同时保留不含密码、验证码或令牌原文的安全审计事件。原邮箱可以重新注册，但会获得新的用户 UUID；当前版本不会联动删除两个业务系统中的业务数据。

**一句话记忆：** 再验一次当前密码，然后删除共享认证账号及全部刷新会话，但保留安全审计记录。

## 主流程速记

```text
注册：申请验证码 → 验证邮箱 → 创建账号和会话 → 签发令牌
登录：验证邮箱和密码 → 创建会话 → 签发令牌
访问：携带 Access Token → 业务服务使用 JWKS 公钥验签
续期：携带 Refresh Cookie → 轮换 Refresh Token → 签发新 Access Token
退出：撤销当前刷新会话 → 清除当前应用 Cookie
重置：验证邮箱 → 修改密码 → 撤销全部刷新会话
注销：验证 Access Token 和当前密码 → 删除认证账号及全部刷新会话
```
